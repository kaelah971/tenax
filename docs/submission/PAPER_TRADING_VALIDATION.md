# Tenax paper-trading log — validation notes

Companion to `tenax-paper-trading-log.csv`. Read-only submission evidence;
nothing here was generated by placing, closing, or altering any order, and no
demo run, mandate, database record, or product file was created or mutated to
produce it. No commit has been made.

## Which rows are provider-backed

Only row 1 (BITGET_DEMO FILLED, order `1491995256369336320`):

- Observed, from the repo + brief as canonical sources: environment
  BITGET_DEMO, symbol NVDAUSDT, direction sell (short hedge), qty 0.42,
  avg fill 236.46, 1x crossed, execution_state FILLED.
- "FILLED" is reported only because the provider explicitly returned it via
  the read-only order-status path (`GET /api/v3/trade/order-info`, FILLED-only
  semantics in `src/lib/bitget/demo-trade.ts`). It is not inferred.

  `proof:v1:EXECUTION_FILLED:act-0003`, receipt `TENAX-1C-flow-0001`
  (see README "Verified Bitget Demo execution" and the 2026-10-08 decision-log
  entry in AGENTS.md).
- BITGET_DEMO uses virtual funds only. Never live money, never mainnet.
- The position was later flattened by a separately authorized close
  (`1491999852949032960` @ 235.72); that close is operational cleanup, and the
  account is flat afterwards. It is not presented as product proof.

## Balance figures — exact source for each

- All three rows: `balance_before` / `balance_after` / `balance_change` were
  NOT observed and are NOT_RECORDED (`BALANCE_CHANGE_NOT_RECORDED` for row 1).
- Why: (a) the canonical run/proof schema contains no balance fields —
  verified by searching `src`, `tests`, `docs`, `scripts` for
  balance_before/balance_after/balance_change (zero hits); the model records
  orderId, avgPrice, cumExecQty, submittedAt, verifiedAt only.
  (b) The Tenax Bitget surface has no historical-equity endpoint: the
  read-only allowlist (`src/lib/bitget/demo-auth.ts`) is exactly
  account/info, account/assets, position, settings, pre-set-leverage,
  unfilled-orders, order-info, and market reads. `GET /api/v3/account/assets`
  (`src/lib/bitget/demo-assets.ts`) returns a point-in-time snapshot only;
  no fills/bills/equity-history endpoint is implemented anywhere in the repo.
- No live provider call was made in this pass: a current-assets GET could only
  return today's balance, never the balance immediately before/after the
  historical fill, so calling it could not answer the question and would only
  risk misreading. Nothing was inferred from notional, fill price, quantity,
  PnL, margin, or fees.
- Rule applied throughout: never infer balance change; report
  BALANCE_CHANGE_NOT_RECORDED rather than fabricate or estimate.

## Production posture

Production execution is currently DRY_RUN. The only provider execution in
Tenax history is the single virtual-funds Demo fill above (plus its cleanup
close). REFUSE / NO ACTION remain valid first-class outcomes, and the
deterministic Mandate Engine — not the model — authorizes.

## Compliance gap

The hackathon asks for per-trade account balance change; for the historical
Demo fill that value is genuinely unavailable (never recorded, not
retrievable). The CSV reports this explicitly instead of filling it.
Everything else requested (timestamp honesty, instrument, direction, price,
quantity, environment, authority outcome, execution state, provider order id)
is present with its evidence type labeled per row.
